Initial Options + Async Search Pattern:

The Security Groups example demonstrates a common UX pattern:

  • Initial State: Shows 5 most frequently used security groups when dropdown opens
  • On Typing: Calls server API to search ALL security groups (after 2+ characters)
  • On Clear: Returns to showing the 5 initial favorites

Search Modes: Filter vs Navigate

Choose between filter mode (hide non-matches) or navigate mode (jump to matches while keeping all visible)

Hides non-matching options (standard behavior)
Keeps all options visible, jumps to matches (highlighted with left border)

When to use each mode:

  • Filter Mode: Large lists where you want to narrow down options (e.g., product catalogs, user lists)
  • Navigate Mode: Quick selection from known lists (e.g., country/state selectors)

Navigate-mode keyboard shortcuts:

  • type — first match becomes focused; all matches keep a left-border highlight
  • Ctrl/Cmd + ↓ — jump to next match
  • Ctrl/Cmd + ↑ — jump to previous match
  • ↑ / ↓ — move focus one option at a time
  • Home / End — jump to first / last option
  • PageUp / PageDown — move 10 options at a time
  • Enter — toggle selection of the focused option
  • Esc — clear the search (or close the dropdown if search is empty)

8. Async Search / Lookup DYNAMIC

Load options dynamically as users type. Perfect for large datasets, API searches, or real-time filtering. 

// searchCallback receives an AbortSignal as its 2nd argument.
// Forward it to fetch — when a newer keystroke supersedes this
// request (or the element is destroyed), the in-flight fetch is
// cancelled instead of racing the newer one.
multiselect.searchCallback = async (searchTerm, signal) => {
    const response = await fetch(`/api/users?search=${searchTerm}`, { signal });
    return await response.json();
};

// Pair with search-debounce="300" to also coalesce keystroke bursts.

const select = document.getElementById('action-buttons-demo');

select.actionButtons = [
  {
    action: 'select-all',
    text: 'Select All',
    tooltip: 'Select all items',
    getIsVisibleCallback: (picker) => {
      const allCount = picker.options.options?.length || 0;

    }
  },
  {
    action: 'clear-all',
    text: 'Clear All',
    tooltip: 'Clear selection',
    getIsVisibleCallback: (picker) => picker.getSelected().length > 0
  },
  {
    action: 'custom',
    text: 'Invert Selection',
    tooltip: 'Invert current selection',
    cssClass: 'custom-invert-btn',
    onClick: (picker) => {
      // Custom action - invert selection
      const allOptions = picker.options.options || [];
      const allValues = allOptions.map(opt => opt.value || opt[0]);
      const selectedValues = picker.getValue();
      const inverted = allValues.filter(v => !selectedValues.includes(v));
      picker.setSelected(inverted);
    }
  },
  {
    action: 'custom',
    text: 'Select Popular',
    tooltip: 'Select most popular languages',
    onClick: (picker) => {
      picker.setSelected(['js', 'ts', 'py']);
    }
  }
];

Features:

  • Built-in actions: 'select-all', 'clear-all' with standard behavior
  • Custom actions: Add any action with custom onClick handler
  • Dynamic visibility: Use getIsVisibleCallback or static isVisible to show/hide buttons based on state
  • Disabled state: Use getIsDisabledCallback or static isDisabled to disable buttons
  • Dynamic text: Use getTextCallback to change button text based on state

  • Dynamic styling: Use getClassCallback or static cssClass to add CSS classes

🔗 Cascading Selects (Reactive Options) NEW

Create dependent dropdowns that automatically update! The options property is reactive - setting element.options = newArray triggers automatic re-rendering. Perfect for Organization → Business Unit → Department flows.

Selected Path:
{
  "organization": null,
  "businessUnit": null,
  "department": null
}

Implementation:

const orgSelect = document.querySelector('#cascade-org');
const buSelect = document.querySelector('#cascade-bu');
const deptSelect = document.querySelector('#cascade-dept');

// Initialize first level
orgSelect.options = organizations;

// When organization changes, update business units
orgSelect.addEventListener('change', async (e) => {
    const orgId = e.detail.selectedValues[0];

    if (orgId) {
        // Fetch business units (simulated async)
        const buOptions = await fetchBusinessUnits(orgId);

        // REACTIVE UPDATE - automatically re-renders!
        buSelect.options = buOptions;
        buSelect.setSelected([]);  // Clear previous selection

        // Clear departments
        deptSelect.options = [];
        deptSelect.setSelected([]);
    } else {
        // Organization cleared - reset cascade
        buSelect.options = [];
        deptSelect.options = [];
    }
});

// When business unit changes, update departments
buSelect.addEventListener('change', async (e) => {
    const buId = e.detail.selectedValues[0];

    if (buId) {
        // Fetch departments (simulated async)
        const deptOptions = await fetchDepartments(buId);

        // REACTIVE UPDATE - automatically re-renders!
        deptSelect.options = deptOptions;
        deptSelect.setSelected([]);
    } else {
        deptSelect.options = [];
    }
});

Key Reactive Behaviors:

  • Automatic re-rendering: Setting element.options = newArray triggers UI update
  • Clear dependent selections: Use setSelected([]) to reset child selects
  • Works with async data: Fetch options from API and assign reactively
  • Proper cleanup: Component destroys/recreates picker for clean state
  • Event-driven: Use 'change' events to chain dependencies

Common Use Cases:

  • Country → State → City selection
  • Category → Subcategory → Product filtering
  • Organization → Department → Team hierarchy
  • Master-detail relationships
  • Conditional option loading

⌨️ Keyboard Hook — redefine key behavior NEW

keydownCallback runs on every keydown before the built-in handling. Return true to fully handle a key (the component then does nothing else for it — you own preventDefault); return falsy to fall through to the defaults. It receives the event, current state, and a controller that mirrors the built-in actions. Open the picker and try the custom keys:

  • j / k — move focus down / up (Vim style)
  • Ctrl/Cmd + a — select all currently-filtered options
  • Ctrl/Cmd + i — invert the selection of the filtered options
  • everything else (arrows, Enter, typing…) still works — those keys fall through
Note: mapping bare j/k means you can no longer type those letters into the search box (the hook claims them). That's fine here — this demo just shows how a hook can remap keys. In a real app you'd bind modifier combos (like the Ctrl/Cmd shortcuts above) or gate a plain key on the dropdown being open with an empty search, so normal typing isn't affected.
Last hook action:
—

Implementation:

picker.keydownCallback = (ctx) => {
    const { key, event, controller, filteredOptions } = ctx;
    // Returning true means YOU fully own the key — call preventDefault() so a
    // printable key like 'j' isn't also typed into the search box.
    if (key === 'j') { event.preventDefault(); controller.focusNext();     return true; }  // Vim down
    if (key === 'k') { event.preventDefault(); controller.focusPrevious(); return true; }  // Vim up
    if ((event.ctrlKey || event.metaKey) && key.toLowerCase() === 'a') {
        event.preventDefault();
        filteredOptions.forEach(o => controller.selectValue(o.value)); // select all shown (no-op if already selected)
        return true;
    }
    if ((event.ctrlKey || event.metaKey) && key.toLowerCase() === 'i') {
        event.preventDefault();
        filteredOptions.forEach(o => controller.toggleValue(o.value)); // invert = toggle each
        return true;
    }
    // return nothing → the built-in handling runs (arrows, Enter, typing, …)
};
