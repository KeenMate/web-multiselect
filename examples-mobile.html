📱 Mobile & Fullscreen

On phones the dropdown opens as a fullscreen overlay instead of a floating panel — a touch-friendly sheet with its own search header, big rows, and a close button. These demos cover the phone-only behaviors: how the presentation is chosen, the soft-keyboard policy, and the touch stand-in for keyboard match-stepping.

1 · mobile-presentation — floating vs fullscreen

The mobile-presentation attribute decides how the open dropdown is presented:

  • auto (default) — a floating panel on desktop, a fullscreen sheet on phones (detected from the environment: touch-primary + a short viewport side under the tablet boundary).
  • floating — always anchor to the input, even on a phone.
  • fullscreen — always present the sheet, even on desktop (handy for previewing the mobile UI, which is what the toggles on this page do).

Because it's usually a phone-only look, every demo below defaults to auto and offers a Preview as fullscreen toggle so you can see the overlay right here on desktop. Close the sheet with the ✕ in its header.

~50 grouped options — on a phone this opens fullscreen automatically.
Show code 
<!-- auto (default): floating on desktop, fullscreen on phones -->
<web-multiselect></web-multiselect>

<!-- force one presentation everywhere -->
<web-multiselect mobile-presentation="floating"></web-multiselect>
<web-multiselect mobile-presentation="fullscreen"></web-multiselect>

2 · fullscreen-autofocus — soft keyboard on phones

By default the keyboard stays closed when the fullscreen sheet opens — it shows the list first, so you can browse long lists and reach the bottom action buttons without the keyboard covering half the screen. The keyboard appears only when you tap the search field. Set fullscreen-autofocus="true" to focus the search on open instead (type-to-filter immediately, like a native picker).

Both pickers use mobile-presentation="auto": a normal floating dropdown here on desktop, a fullscreen sheet on a phone — where the keyboard difference actually shows. Tick Preview as fullscreen to see the overlay on desktop.

On a phone: the list shows, search is not focused.
On a phone: search is focused, keyboard pops on open.
Show code 
<!-- default: keyboard stays closed until the user taps the search field -->
<web-multiselect></web-multiselect>

<!-- opt in to auto-focus + soft keyboard on open -->
<web-multiselect fullscreen-autofocus="true"></web-multiselect>

// or via property
el.fullscreenAutofocus = true;

3 · filter vs navigate — live switch

search-mode decides what typing does. In filter (the default) non-matches are hidden and the list shrinks to the results. In navigate the list stays whole and typing jumps focus between matches instead. On desktop you step through matches with Ctrl+↑/↓ — but touch has no such shortcut, so in the fullscreen overlay a match navigator appears under the search box: a N of M count plus prev/next buttons that walk the matches. It shows only in navigate mode, only once you type, and the buttons disable when nothing matches.

Type (e.g. e) to feel the difference in the same overlay. There are two ways to switch here: the built-in toggle — the leading icon in the overlay's search bar (magnifier = navigate, funnel = filter), enabled with show-search-mode-toggle — flips the mode in place without closing the sheet; the host-page radios below do the same by setting the search-mode attribute. The picker uses mobile-presentation="auto", so on desktop it's a normal floating dropdown — tick Preview as fullscreen to force the overlay and reveal the built-in toggle.

Search mode:
Fullscreen: tap the leading icon in the search bar to switch. navigate: type, then use the ↑/↓ next to the count to jump. filter: the list narrows to matches.
Show code 
<!-- navigate mode + a built-in in-overlay mode toggle (fullscreen only) -->
<web-multiselect search-mode="navigate" show-search-mode-toggle></web-multiselect>

<!-- show-search-mode-toggle adds a clickable icon at the search field's leading
     edge in the fullscreen sheet; tapping it flips filter<->navigate in place. -->

<!-- Or switch from the host page — it's just an attribute -->
picker.setAttribute('search-mode', 'filter');   // or 'navigate'

<!-- On phones (fullscreen overlay) navigate mode adds a count + prev/next
     navigator under the search box automatically. Desktop uses
     Ctrl+ArrowUp / Ctrl+ArrowDown for the same jumps. -->

4 · RTL — right-to-left, overlay included

Give the element (or any ancestor) dir="rtl" and the whole component mirrors: the toggle icon and in-input counter move to the left, checkboxes sit on the right of each row, the matched-item accent bar flips sides, badges reverse, and — the part that used to be left-behind — the fullscreen overlay mirrors too (search + close swap sides, and the navigate-mode match navigator flips count vs. prev/next). It's all driven by CSS logical properties off the inherited direction, so there's nothing to configure beyond dir.

Tick Preview as fullscreen and open the picker to see the overlay mirror too — including the navigate-mode match navigator (this one uses search-mode="navigate").

Checkbox on the right, toggle on the left, navigator mirrored.
Show code 
<!-- on the element… -->
<web-multiselect dir="rtl"></web-multiselect>

<!-- …or inherited from any ancestor -->
<div dir="rtl">
  <web-multiselect></web-multiselect>
</div>
